# Device mode (Workstream M)

A lock key that makes the app behave like a physical device with buttons, keeps the screen on, and dims to a minimal always-on display (AOD).

## States and rules (`src/devicemode/state.js`, pure, injected clock, never throws)

State `{ locked, wake, aod, notice }`.

* **Lock** is the user's switch. Locked implies **wake** (keep-awake) until the inactivity timeout.
* **Keep-awake timeout** (Never / 5 / 15 / 30 / 60 min, default 30): no touch, button or key for that long releases the wake hold (the OS may then dim/sleep). The lock stays. Next activity re-takes the hold and shows a small notice ("Screen hold released after N min..."). "Never time out while music plays" (default ON): the clock is parked while a source plays and restarts when it stops.
* **AOD** (Off / 30 s / 1 min / 5 min, default 1 min): after that much inactivity while locked and awake. In AOD a single stray touch does nothing; AOD buttons work directly (and keep the hold alive without leaving AOD). Exit: double-tap anywhere (default), long-press anywhere, or tap the lock key (setting); also unlock, and returning to the app after it was hidden.
* **Restart**: a fresh launch starts UNLOCKED unless "Stay locked after restart" is on (safety rule).
* **Fail-safes**: the unlock control always works (keyboard Enter / Space-hold, and an assistive-tech click with detail 0 toggles directly); Android back does not unlock (a history sentinel is pushed while locked; back re-pushes it and shows "Hold the lock key to unlock"); any internal error (`machine.fail()`, allowlist exception) drops to UNLOCKED.

## Settings (`settings.js`, key `runout.devicemode.v1`, versioned, validated)

persistLock(off), unlockMethod(hold|double|slide), fxPadWhileLocked(off), dimFrozen(on), keepAwakeMin(30), neverTimeoutPlaying(on), aodEnabled(on), aodIdleSec(60), aodWake(double), aodBrightnessPct(8, 1-40), aodLowRefresh(on), pixelShift(on), glowPct(30, 10-60). All tunables live in `SPEC`. B's Settings page hosts a Device mode group (opens `sheet.js`); the gear next to the lock key opens the same sheet. Migration into `runout.settings.v1` is a later one-liner.

## The lock key (`lockkey.js`)

Recessed housing, sliding thumb with a padlock, LED lit when locked, 44 px target, `aria-pressed`, label "Lock controls" / "Hold to unlock". In every page header (`.page-actions`, rightmost) plus a floating copy (bottom right) while the cassette player covers the header. Tap = lock + haptic (existing `haptics` setting). Unlock = hold 0.8 s with a filling ring (default), double-tap, or slide. No sound (no sound setting exists).

## The frozen face (one mechanism)

`body[data-devicemode~="locked"]` makes everything `pointer-events:none; touch-action:none; user-select:none; overscroll-behavior:none`; the per-section allowlist (generated by `faces.js faceCss`) re-enables `pointer-events:auto` on the live selectors only. A capture-phase guard in `index.js` uses the SAME allowlist for what CSS cannot stop (keyboard, TalkBack click, wheel, context menu, selectstart, touchmove). Frozen areas get `opacity:.84` on leaf elements (setting `dimFrozen`).

* `deviceMode.allowsGesture(kind)` (`guard.js`): live while locked: `button key wind-hold slider`; `fx-pad` only with the setting; everything else false. Already consulted by the drawer drag (`shell/nav.js`) and the FX pad (`fx/ui.js`). T1/T2/D may call it from their own entry points (CSS already prevents the events).
* `registerLockFace(sectionId, { buttons, aod, aodText, notes })`. Add `data-lock-ok` to any control instead of editing selectors. A press on a live control inside an element marked `data-lock-surface` is stopped from bubbling into that surface. Unregistered section: generic `button/[role=button]/[role=switch]` allowlist + console warning (never throws; the coverage test warns).
* Defaults (`default-faces.js`): Albums: Play/Stop, 33/45/78, -/+, prev/next (+ CD keys, speed slider); platter, tonearm, pinch, library, display toggle, drawer, search frozen. Mixtapes: cassette player `[role=button]` keys (transport, wind, AUTO, FLIP, eject) live, skin chips, shelf, editor frozen (open the player before locking). Radio: Stop controls live, dial and lists frozen (hint says so). Booth: FX mode rows/chips live, pad frozen unless the setting. Settings: frozen. Hamburger, drawer, edge strip frozen always.

## AOD (`devicemode.css`, `index.js`, `framegate.js`, `aodhooks.js`)

Theme layer, not a second UI: `body[data-devicemode~="aod"]` sets true #000, drops backgrounds/shadows/filters/animations, hides canvases/img/svg `<image>`, draws SVG as hairlines, text transparent except the now-playing title (`.dm-np`) and `aodText`; AOD buttons get an accent outline + soft glow at `glowPct`% luminance. Fade 160 ms (instant with reduced motion). Pixel shift (`pixelshift.js`: 13 positions, stride 5, per minute) via `translate` on the shell. **Low refresh**: `frameGate` swaps `window.requestAnimationFrame` for a 1 Hz version while AOD is on (every loop is throttled with no edits; restored on exit; parked loops go back to the real rAF); audio runs on the audio thread and is untouched. Native: brightness `aodBrightnessPct`/100 and preferred refresh 1 Hz (closest supported mode) via DeviceDisplay; restored on exit, unlock, hide. Renderer hook: `onAodOutlineMode(cb)` / `setAodOutlineMode(bool)` in `aodhooks.js` (until a stage subscribes, CSS hides its layers).

## Native plugin decision

`npm view`: `@capacitor-community/keep-awake` 5.0.1 is the Capacitor-6 line (peer `@capacitor/core ^6`, MIT); its Android source is only `addFlags/clearFlags(FLAG_KEEP_SCREEN_ON)`. `@capacitor-community/screen-brightness` 6.x exists (MIT) but nothing covers preferred refresh rate. Three capabilities, two dependencies, still no refresh rate: so ONE small custom plugin, `native/android-display/DeviceDisplayPlugin.java` (`keepAwake`, `setBrightness`, `setPreferredRefreshRate`, `getInfo`), no new npm dependency. `FLAG_KEEP_SCREEN_ON`, `screenBrightness` and `preferredRefreshRate` need NO manifest permission (WAKE_LOCK is not needed). Refresh: `LayoutParams.preferredRefreshRate` (API 21+) plus `preferredDisplayModeId` (API 23+, same-resolution mode closest to the request); both are hints the system may ignore. `Surface.setFrameRate` was not used (needs a Surface; no clean public route from a WebView). minSdk is 22 (guards on API 23). Overrides are dropped in `handleOnPause`, re-applied in `handleOnResume`.

JS side: `keepawake.js` prefers the plugin, else `navigator.wakeLock` (re-acquired on visibilitychange, release events, NotAllowedError, unsupported), else reports `mode:'none'` and the UI says the screen may still sleep.

## CI

`scripts/apply-android-display.mjs` (idempotent; exit 1 with `::error::` if an anchor is missing) copies the Java (package retargeted) and registers it in `MainActivity` before `super.onCreate` (custom plugins are registered in code; `capacitor.plugins.json` only lists npm plugins, so it is untouched). Works in either order with L's script (tested against the stock template and an already-patched one). Step "Install Runout display plugin" in `android.yml` between L's step and `cap sync`. The debug APK build is the compile check (Java also linted with javac against stubs).

## Add a section face

1. `registerLockFace('id', { buttons: [...], aod: [...], aodText: [...], notes: '...' })` in your mount code (or add to `DEFAULT_FACES`).
2. Mark controls `data-lock-ok`; mark gesture surfaces `data-lock-surface`.
3. Call `allowsGesture(kind)` in new gesture entry points; use `frameGate`/plain rAF (gated automatically) and `onAodOutlineMode`.

## Failure modes

No native plugin: wake lock or none. Wake lock denied (battery saver): hint shown. Lock face selector invalid: drops to unlocked. Page hidden: OS owns the screen; return counts as a deliberate wake.
